# درون‌ریز دمو سایه (Saayeh Demo Importer)

افزونه‌ی وردپرس برای درون‌ریزی یک‌کلیکی محتوای دمو پوسته‌های «سایه»: محصولات متغیر ووکامرس، دسته‌ها، ویژگی‌ها، برگه‌ها، نوشته‌ها، منوها، تنظیمات قالب، کوپن‌ها و حمل‌ونقل — و حذف کامل همه‌ی آن‌ها با یک دکمه.

- رابط کاملاً فارسی و راست‌چین، هماهنگ با پیشخوان وردپرس
- درون‌ریزی مرحله‌به‌مرحله با AJAX، نوار پیشرفت، گزارش زنده و «تلاش دوباره»
- قابل ادامه پس از قطعی (وضعیت در پایگاه داده نگه داشته می‌شود)
- ایدمپوتنت: اجرای دوباره چیزی را تکراری نمی‌سازد
- پشتیبان‌گیری از تنظیمات و بازگردانی کامل هنگام حذف دمو
- توسعه‌پذیر با فیلتر و اکشن برای پوسته‌های آینده

**پیش‌نیازها:** وردپرس ۶٫۴+، PHP 7.4+، ووکامرس ۸+ (برای دموهایی که `"requires": ["woocommerce"]` دارند).

## نصب

1. فایل `saayeh-demo-importer.zip` را از «افزونه‌ها ← افزودن ← بارگذاری افزونه» نصب و فعال کنید.
2. ووکامرس را نصب و فعال کنید (اگر فعال نباشد، صفحه‌ی درون‌ریز پیوند نصب را نشان می‌دهد).
3. پوسته‌ی «سایه» (یا هر پوسته‌ای که بسته‌ی دمو اعلام کرده) را فعال کنید.

## استفاده

1. به **نمایش ← درون‌ریزی دمو** بروید (یا از پیوند «درون‌ریزی دمو» در فهرست افزونه‌ها).
2. برای هر پوسته یک کارت می‌بینید با تصویر، نسخه، وضعیت (`نصب نشده` / `نصب‌شده، غیرفعال` / `فعال`) و خلاصه‌ی دمو (تعداد محصول، برگه، نوشته و تصویر).
3. در کارت پوسته‌ی فعال، گزینه‌ها را انتخاب کنید: محصولات، برگه‌ها، نوشته‌ها، منوها، تنظیمات قالب، کوپن و حمل‌ونقل (همه به‌صورت پیش‌فرض روشن).
4. روی **درون‌ریزی دمو** بزنید و در پنجره‌ی تأیید، ادامه دهید. پیشرفت و گزارش هر مرحله نمایش داده می‌شود.
5. اگر خطایی رخ داد یا اتصال قطع شد، **تلاش دوباره** را بزنید؛ اگر صفحه بسته شد، دفعه‌ی بعد پیام «ادامه‌ی درون‌ریزی» نمایش داده می‌شود.
6. برای پاک‌کردن همه‌چیز، **حذف محتوای دمو** را بزنید. فقط چیزهایی که درون‌ریز ساخته حذف می‌شوند و برگه‌ی نخست، برگه‌های ووکامرس، جایگاه منوها و گزینه‌های تغییرکرده به حالت قبل برمی‌گردند.

### ترتیب مراحل

تصاویر ← ویژگی‌ها ← دسته‌بندی محصولات ← محصولات و متغیرها ← برگه‌ها ← نوشته‌ها ← منوها ← کوپن‌ها ← حمل‌ونقل ← تنظیمات قالب و گزینه‌ها ← نهایی‌سازی (بازسازی پیوندهای یکتا).

تصاویر و محصولات در دسته‌های کوچک (به‌ترتیب ۳ و ۳ مورد در هر درخواست) پردازش می‌شوند تا روی هاست‌های اشتراکی به محدودیت زمان اجرا نخورند.

## اعلام بسته‌ی دمو در یک پوسته‌ی جدید

۱) در هدر `style.css` پوسته این خط را اضافه کنید (مسیر نسبت به ریشه‌ی پوسته):

```css
/*
Theme Name: نام پوسته
...
Saayeh Demo Package: demo/demo.json
*/
```

۲) فایل `demo/demo.json` و تصاویر آن (مثلاً `demo/images/`) را کنار پوسته قرار دهید. مسیر تصاویر ابتدا نسبت به پوشه‌ی `demo.json` و سپس نسبت به ریشه‌ی پوسته جست‌وجو می‌شود. هر فایلی بیرون از پوشه‌ی پوسته رد می‌شود.

۳) (اختیاری) نامک پوسته را به فهرست پوسته‌های شناخته‌شده اضافه کنید تا پیش از نصب هم با وضعیت «نصب نشده» نمایش داده شود:

```php
add_filter( 'sdi_known_themes', function ( $themes ) {
	$themes['my-theme'] = 'پوسته‌ی من';
	return $themes;
} );
```

**پوسته‌ی فرزند:** اگر پوسته‌ی فرزندِ یک پوسته‌ی دارای بسته فعال باشد و خودش هدر نداشته باشد، بسته‌ی پوسته‌ی والد استفاده می‌شود و کارت والد «فعال (از طریق پوسته‌ی فرزند)» نشان داده می‌شود. تنظیمات قالب روی پوسته‌ی فرزند ذخیره می‌شوند.

### مرجع طرح demo.json (نسخه ۱)

| بخش | توضیح |
|---|---|
| `version` | باید `1` باشد. |
| `theme` | نامک پوسته (اطلاعاتی؛ پرچم دمو از نام پوشه‌ی پوسته گرفته می‌شود). |
| `requires` | فهرست پیش‌نیازها، مثلاً `["woocommerce"]`. موارد دیگر به‌صورت `slug/slug.php` بررسی می‌شوند. |
| `images[]` | `id`، `file`، `alt`، `title`. هر تصویر با `media_handle_sideload` از یک کپی موقت بارگذاری می‌شود. |
| `product_attributes[]` | `slug`، `name`، `terms` (رشته یا `{name, slug, hex}`). ویژگی سراسری ساخته می‌شود؛ `hex` در متای `saayeh_color_hex` ذخیره می‌شود. |
| `product_categories[]` | `slug`، `name`، `image` (شناسه‌ی تصویر → `thumbnail_id`)، اختیاری: `parent`، `description`. |
| `products[]` | `slug`، `name`، `type` (`variable`/`simple`)، `regular_price`، `sale_price` (یا `null`)، `short_description`، `description` (HTML)، `categories` (نامک)، `tags` (نام)، `image`، `gallery`، `featured`، `badge` (→ متای `_saayeh_badge`)، `attributes` (`{"size": ["S","M"], "color": ["caramel"]}`)، `out_of_stock`، اختیاری: `sku`. |
| `pages[]` | `slug`، `title`، `content`، `role`، `template`. نقش‌ها: `front`، `blog`، `shop`، `cart`، `checkout`، `myaccount`، `terms` یا خالی. برای cart/checkout/myaccount با محتوای خالی، شورت‌کد ووکامرس درج می‌شود. |
| `posts[]` | `slug`، `title`، `excerpt`، `content`، `image`، `categories` (نام)، اختیاری: `tags`، `date`. |
| `menus[]` | `location`، `name`، `items[]`. انواع آیتم: `page`، `post`، `product` (با `ref` = نامک)، `shop`، `product_cat`، `category`، `product_tag` (با `ref`)، `home`، `custom` (`title`، `url`). هر آیتم می‌تواند `title` و `children` داشته باشد. |
| `coupons[]` | `code`، `discount_type` (`percent`/`fixed_cart`/`fixed_product`)، `amount`، `description`، اختیاری: `minimum_amount`، `maximum_amount`، `usage_limit`، `free_shipping`، `individual_use`، `date_expires`. |
| `theme_mods` | کلید ← مقدار؛ با `set_theme_mod` ذخیره می‌شود. |
| `options` | کلید ← مقدار؛ با `update_option`. گزینه‌های حساس (مثل `siteurl`، `admin_email`، `default_role`، `active_plugins`) هرگز تغییر نمی‌کنند. |
| `shipping` | `zone`، `methods[]` (`flat_rate` با `cost`، `free_shipping` با `min_amount`)، اختیاری: `locations` (کد کشور؛ پیش‌فرض از `woocommerce_default_country` یا `IR`). |

**قانون `out_of_stock`:** آرایه‌ای از شرط‌ها؛ هر متغیری که با همه‌ی کلیدهای یک شرط بخواند «ناموجود» می‌شود. مثال: `[{"size":"XL"}, {"size":"S","color":"black"}]`. برای محصول ساده `true` بنویسید.

**توکن‌های تصویر:**
- `"@image:<id>"` در هر جای مقادیر `theme_mods` و `options` (حتی داخل آرایه) با شناسه‌ی پیوست جایگزین می‌شود؛ اگر کل مقدار همین توکن باشد، عدد صحیح ذخیره می‌شود.
- `{{image_url:<id>}}` در محتوای برگه، نوشته و توضیحات محصول با نشانی تصویر جایگزین می‌شود.

نمونه‌ی کامل در `tests/fixtures/sdi-fixture-theme/demo/demo.json` موجود است.

## داده‌ها و حذف

- هر شیء ساخته‌شده متای `_sdi_demo` (= نامک پوسته) و `_sdi_key` (= کلید آن در demo.json) می‌گیرد؛ برای ترم‌ها به‌صورت term meta. بر همین اساس اجرای دوباره موارد موجود را رد می‌کند.
- ترم‌ها یا ویژگی‌هایی که از قبل در سایت بوده‌اند استفاده می‌شوند ولی پرچم نمی‌خورند و هنگام حذف دست نمی‌خورند.
- پیش از اولین درون‌ریزی از `show_on_front`، `page_on_front`، `page_for_posts`، شناسه‌ی برگه‌های ووکامرس، `nav_menu_locations` و همه‌ی گزینه‌ها/تنظیمات قالبی که دمو تغییر می‌دهد پشتیبان گرفته می‌شود.
- گزینه‌های افزونه: `sdi_state`، `sdi_backup`، `sdi_imported`، `sdi_registry`. حذف افزونه (uninstall) فقط همین گزینه‌ها را پاک می‌کند؛ محتوای دمو را پیش از حذف افزونه از صفحه‌ی درون‌ریز پاک کنید.

## توسعه‌پذیری

| هوک | نوع | کاربرد |
|---|---|---|
| `sdi_import_steps` | فیلتر | افزودن/حذف/جابه‌جایی مراحل. هر مرحله: `['label' => ..., 'callback' => callable, 'group' => 'products'\|null]`. callback ورودی `( SDI_Importer $importer, int $cursor )` می‌گیرد و `['done' => bool, 'cursor' => int, 'total' => int]` برمی‌گرداند. |
| `sdi_before_step` / `sdi_after_step` | اکشن | پیش/پس از هر واحد کار یک مرحله. |
| `sdi_option_groups` | فیلتر | گزینه‌های قابل انتخاب در کارت. |
| `sdi_known_themes` | فیلتر | پوسته‌های شناخته‌شده. |
| `sdi_batch_size` | فیلتر | اندازه‌ی دسته برای هر مرحله. |
| `sdi_remove_batch_size` | فیلتر | تعداد مورد حذف‌شده در هر درخواست. |
| `sdi_requirement_met` | فیلتر | بررسی سفارشی پیش‌نیازها. |
| `sdi_protected_options` | فیلتر | فهرست گزینه‌هایی که دمو اجازه‌ی تغییرشان را ندارد. |
| `sdi_menu_item_args` | فیلتر | پشتیبانی از انواع جدید آیتم منو. |
| `sdi_shipping_method_settings` | فیلتر | تنظیمات روش‌های حمل. |
| `sdi_page_role` | اکشن | نقش‌های سفارشی برگه. |
| `sdi_import_started` / `sdi_import_completed` / `sdi_after_remove` | اکشن | رویدادهای چرخه‌ی کار. |

نمونه — افزودن یک مرحله‌ی سفارشی پیش از نهایی‌سازی:

```php
add_filter( 'sdi_import_steps', function ( $steps, $importer ) {
	$final = array_pop( $steps ); // finalize
	$steps['my_widgets'] = array(
		'label'    => 'ابزارک‌ها',
		'group'    => 'theme_settings',
		'callback' => function ( $importer, $cursor ) {
			// ... از $importer->package->data و $importer->image_id( 'hero' ) استفاده کنید.
			$importer->log( 'ابزارک‌ها اعمال شد.', 'success' );
			return array( 'done' => true );
		},
	);
	$steps['finalize'] = $final;
	return $steps;
}, 10, 2 );
```

## امنیت

- همه‌ی درخواست‌ها با nonce و قابلیت `manage_options` بررسی می‌شوند؛ ورودی‌ها پاک‌سازی و خروجی‌ها escape می‌شوند.
- فایل‌ها فقط از داخل پوشه‌ی پوسته خوانده می‌شوند (بررسی با `realpath`) و فقط انواع تصویر مجاز بارگذاری می‌شوند.
- همه‌ی فایل‌های PHP دسترسی مستقیم را مسدود می‌کنند (`ABSPATH`).
- هیچ کلید یا رمزی در کد وجود ندارد و افزونه هیچ درخواست خارجی نمی‌فرستد.

## آزمون

آزمون دود سرتاسری (۷۹ بررسی) روی وردپرس واقعی با ووکامرس اجرا می‌شود و هندلرهای AJAX را با nonce و قابلیت واقعی صدا می‌زند:

```bash
cp -r tests/fixtures/sdi-fixture-theme wp-content/themes/
wp plugin activate woocommerce saayeh-demo-importer
wp theme activate sdi-fixture-theme
wp eval-file wp-content/plugins/saayeh-demo-importer/tests/smoke-test.php
```

پوسته‌ی نمونه عمداً یک تصویر با مسیر `../../etc/hostname`، یک آیتم منوی ناموجود و تلاش برای تغییر `admin_email` دارد تا رد شدن آن‌ها هم آزموده شود.

## مشارکت

مشارکت شما خوشحال‌مان می‌کند:

1. مخزن را fork کنید و یک شاخه‌ی جدید بسازید (`feature/...` یا `fix/...`).
2. از [استانداردهای کدنویسی وردپرس](https://developer.wordpress.org/coding-standards/wordpress-coding-standards/php/) پیروی کنید؛ پیشوند `sdi_`/`SDI_` و دامنه‌ی ترجمه‌ی `saayeh-demo-importer` را رعایت کنید. رشته‌های رابط کاربری فارسی‌اند.
3. پیش از ارسال: `php -l` روی همه‌ی فایل‌ها و اجرای `tests/smoke-test.php`. اگر طرح demo.json را تغییر می‌دهید، پوسته‌ی نمونه و جدول بالا را به‌روز کنید.
4. یک Pull Request با توضیح تغییر و نحوه‌ی آزمودن آن باز کنید.
5. مشکلات امنیتی را به‌صورت عمومی گزارش نکنید؛ از گزینه‌ی «Report a vulnerability» در GitHub استفاده کنید.

با ارسال مشارکت، می‌پذیرید که کدتان تحت مجوز GPL-2.0-or-later منتشر شود.
